# PairMaster Firestore Security Specification

## 1. Data Invariants (Master Source of Truth)
1. **Default-Deny Catch-All**: Every path not explicitly matched under `/databases/{database}/documents` is denied (`allow read, write: if false`).
2. **Verified or Scoped-Anonymous Identity Required for Writes**: Private `/users/{userId}` writes strictly require `request.auth.token.email_verified == true`. Public `/leaderboard/{entryId}` writes allow either a verified user (`email_verified == true`) or a Firebase Anonymous Auth user (`request.auth.token.firebase.sign_in_provider == 'anonymous'`) strictly constrained to `displayName == '唔知邊個(unknown)'`.
3. **Strict Path & ID Guard**: Single-document operations (`get`, `create`, `update`, `delete`) validate document IDs with `isValidId(id)` (`^[a-zA-Z0-9_\\-]+$`, length `1..128`). List operations never run `isValidId()`.
4. **PII Isolation**: User emails, addresses, and private credentials are never stored in `/users/{userId}` or `/leaderboard/{entryId}`. `/users/{userId}` and its subcollections (`/scores`, `/customThemes`, `/compatibilityLogs`) are readable and writable **only** by `isOwner(userId)` (`request.auth.uid == userId`).
5. **Master Gate Parent Existence**: All subcollections under `/users/{userId}` (`scores`, `customThemes`, `compatibilityLogs`) verify `exists(/databases/$(database)/documents/users/$(userId))` on create/update (unless created atomically in a batch using `existsAfter`, so the client ensures the parent `/users/{userId}` document exists first or uses `existsAfter`). Let's ensure the client creates `/users/{userId}` before subcollection writes AND rules check `exists(/databases/$(database)/documents/users/$(userId))`.
6. **Public Leaderboard Integrity**: `/leaderboard/{entryId}` allows `list` ONLY when `resource.data.isPublic == true` OR (`isSignedIn() && resource.data.userId == request.auth.uid`) (explicitly evaluated on `resource.data`, zero `get()`/`exists()` inside `allow list`), and `get` when non-existent (`resource == null`), public (`resource.data.isPublic == true && resource.data.highScore >= 0`), or owned by the caller. Creates to `/leaderboard/{entryId}` require `canWriteLeaderboard(incoming())`, `incoming().userId == request.auth.uid`, and `entryId == (request.auth.uid + '_' + incoming().gameMode + '_' + incoming().difficultyId + '_' + incoming().themeId)` (so players can never overwrite another user's entry). Updates allow either the owning player (scoped by UID and entryId) OR `isAdmin()` modifying strictly `['displayName', 'updatedAt']` while keeping all scores/metadata immutable. Deletes allow either the owning player or `isAdmin()`. Anonymous users cannot set any `displayName` other than `'唔知邊個(unknown)'`.
7. **Temporal & Ownership Immutability**: `createdAt == request.time` on `create`; `updatedAt == request.time` on both `create` and `update`; `createdAt`, `uid`/`userId` are immutable on `update`.
8. **Strict Key & Type Blueprints**: Every `create` verifies `keys().hasAll(...) && keys().hasOnly(...)`; every `update` calls `isValid[Entity](incoming())` first AND restricts changed keys via `incoming().diff(existing()).affectedKeys().hasOnly([...])`.
9. **Admin-Only Daily Notices (`birthday` & `confession`)**: `/dailyNotices/{noticeId}` only allows doc IDs `'birthday'` and `'confession'` (`noticeId == incoming().type`), enforcing at most 1 slot per type per `activeDate`. Only `isAdmin()` (verified super-admin email `yui1218.cc@gmail.com` or verified UID listed in `/admins/{uid}`) may create, update, or delete notices. Public reads (`list`) strictly require `resource.data.isActive == true`.
10. **Booking Queue, Spoiler-Free Slots & Time-Gated Scheduling**: Visitors can submit booking requests into `/noticeRequests/{requestId}` strictly with `status == 'pending'`, `requesterUid == request.auth.uid`, and `createdAt == request.time` (guaranteeing chronological first-come-first-served ordering). Only `isSuperAdmin()` or the request's owner (`resource.data.requesterUid == request.auth.uid`) can read requests; only `isAdmin()` can approve/reject. `/reservedSlots/{slotId}` reveals ONLY `{ slotId, type, targetDate, isBooked }` without message spoilers; `/scheduledNotices/{slotId}` enforces `activateAt <= request.time && expireAt > request.time` on public `get` so future approvals remain hidden until 00:00 Hong Kong time on `targetDate`.
11. **Optional Compressed Photo Upload Guard (`photoDataUrl`)**: `DailyNotice`, `NoticeRequest`, and `ScheduledNotice` permit an optional `photoDataUrl` string capped at `250000` characters (~250KB, strictly safely under Firestore's 1MB doc limit) and strictly prefixed with `data:image/jpeg;base64`, `data:image/png;base64`, or `data:image/webp;base64` (blocking SVG/HTML/script URIs). On `update` in `/noticeRequests`, `photoDataUrl` is immutable (`affectedKeys().hasOnly(['status', 'reviewedAt'])`).
12. **Unique-Per-Device Visitors Analytics (`/visitors/{deviceId}`)**: Each browser/device writes strictly one document keyed by its local `deviceId`. Only `isSuperAdmin()` may `list` or `delete` `/visitors`. Creates require `visitCount == 1` and server timestamps; updates require monotonic `visitCount` (`existing <= incoming <= existing + 1`) and prevent anonymous users from overwriting a known device label/name. Super Admin may also rename or remove visitor rows.

## 2. The "Dirty Dozen" Attack Payloads (All Expected: PERMISSION_DENIED)
1. **Shadow Field Injection on Profile**: Create `/users/{uid}` with `{ uid, displayName: "Mochi", isAdmin: true, createdAt: serverTime, updatedAt: serverTime }` -> Rejected by `keys().hasOnly(['uid', 'displayName', 'photoURL', 'favoriteMbti', 'createdAt', 'updatedAt'])`.
2. **Identity Spoofing on Score**: User A writes `/users/{userA}/scores/s1` with `userId: "{userB}"` -> Rejected by `data.userId == request.auth.uid`.
3. **Unverified Email or Spoofed Anonymous Name Write**: Authenticated non-anonymous user with `email_verified: false` OR anonymous user trying to submit `displayName: "Admin"` to `/leaderboard/{uid}_flip_easy_candy` -> Rejected by `canWriteLeaderboard(incoming())`.
4. **Cross-User Subcollection Read**: User B attempts `get` or `list` on `/users/{userA}/compatibilityLogs` -> Rejected by `isOwner(userId)`.
5. **Leaderboard Entry Hijack**: User B attempts to `update` `/leaderboard/{userA}_flip_easy_candy` -> Rejected by `existing().userId == request.auth.uid` and doc ID prefix check.
6. **Leaderboard Private Scraping**: Attacker queries `/leaderboard` without filtering `where('isPublic', '==', true)` when a document has `isPublic: false` -> Rejected by `allow list: if resource.data.isPublic == true && resource.data.highScore >= 0`.
7. **Timestamp Forgery**: Client submits `/users/{uid}` with `createdAt: "2020-01-01T00:00:00Z"` or client `Date` -> Rejected by `data.createdAt == request.time && data.updatedAt == request.time`.
8. **Immutable Field Mutation**: Client updates `/users/{uid}/scores/s1` changing `createdAt` or `gameMode` -> Rejected by `affectedKeys().hasOnly(...)` and `incoming().createdAt == existing().createdAt`.
9. **ID Poisoning (1.5KB Document ID)**: Client creates `/users/{uid}/scores/{1500_char_junk}` -> Rejected by `isValidId(scoreId)`.
10. **Array Exhaustion ("Denial of Wallet")**: Client creates `/users/{uid}/customThemes/t1` with `items` containing 500 objects or an invalid first element (`items: ["bad"]`) -> Rejected by `data.items is list && data.items.size() >= 6 && data.items.size() <= 24 && data.items[0] is map`.
11. **Value Poisoning on Leaderboard**: Client updates `/leaderboard/{uid}_flip_easy_candy` with `highScore: "999999999"` (string) or `highScore: -50` or `stars: 99` -> Rejected by `isValidLeaderboardEntry(incoming())` (`highScore is number && highScore >= 0 && highScore <= 1000000`, `stars is int && stars >= 1 && stars <= 3`).
12. **Non-Admin DailyNotice / Self-Admin Escalation**: Regular user or unverified email spoof attempts to write `/dailyNotices/birthday` or add themselves to `/admins/{uid}` -> Rejected by `isAdmin()` and `isSuperAdmin()`.
